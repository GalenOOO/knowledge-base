# 学习开源项目

> 本文档目的：规定学习一个开源项目时的目标分档、阅读顺序与产出。

## 1. 目标

学习前只定一个主目标，深度随目标停：

| 目标 | 停的标准 |
|------|----------|
| 会用 | 跑通官方示例，知道常用配置 |
| 懂设计 | 能说清：解决什么、核心抽象是什么、故意没做什么 |
| 能改 | 能指出扩展点，并改过一处最小改动 |

下面步骤按「懂设计」写。会用做到 2.2 即停；能改在第 3 节产出之后再做一处最小改动。

## 2. 步骤

### 2.1 读它怎么介绍自己

不打开 `src/`。读 README、官网、官方 demo，先写出一句话：

> 这是一个 ___，给 ___ 用，靠 ___ 做到 ___。故意不做 ___。

写不出这一句，不进入后续步骤。

### 2.2 跑最小例子

按官方 quickstart 跑通一条路径。先建立「用起来是什么样」，再读它如何被造出来。

跑不通时记下卡点（环境、权限、文档过期），不在环境问题上耗死。

### 2.3 找脊柱

只找真正干活的主路径，其余当配件（插件、UI、适配、脚手架）。

脊柱通常在：

- 入口：`main` / CLI / `index`
- 主循环或主抽象
- 核心类型：一次任务、一次请求、一次工具调用分别是什么

| 类型 | 脊柱 |
|------|------|
| Agent / harness | model ↔ tool 循环 |
| Web 框架 | 请求生命周期 |
| 编译器 | 源码 → 中间表示 → 产物 |
| 数据库 | 查询路径 |

三个问题：

- 数据从哪进、到哪出？
- 中间不可替换的是哪一段？
- 加能力时，作者希望插在哪？

### 2.4 带着问题读

每次只追一个问题，追到答案就停，写一行笔记。不从 `utils/`、配置文件或目录字母序开始。

### 2.5 写一页对照

按第 3 节字段写下产出。然后用同一组问题对照 **1 个同类项目**。

## 3. 产出

一页即可：

- **定位**：在同类里站哪一端
- **取舍**：默认给什么、故意留给扩展的是什么
- **结构**：哪几层、主循环在哪
- **扩展点**：能插什么、不能动什么
- **不适用**：什么任务它默认不够

细节仍以代码为准，不写教程式调用链。

从「懂设计」进到「能改」：改一个最小点（加一个扩展、换一个配置、断掉某步看失败方式）。

## 4. 不要做什么

- 从目录树第一个文件读到最后一个
- 先把依赖、构建、CI 搞懂再看主路径
- 记录「第几行调用了什么」
- 没有问题就让 AI「把这个项目讲一遍」
