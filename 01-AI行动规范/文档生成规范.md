# 文档生成规范

> 本文档目的：规定生成各类文档时写什么、不写什么。

## 1. 总原则

按文档职能分，不按文件名。

| 职能 | 正文 |
|------|------|
| 目标态 | 对象是什么、怎么做、本对象的硬约束 |
| 过程态 | 为什么、比过什么、不选什么 |
| 操作（混合） | 步骤用正面写；「不要」只保留本操作硬约束 |

必须：每份文档只写该对象需要的内容；指向其他对象用链接。
必须：约束能改写成正面规则则改写。
禁止：把对话纠偏原样写入目标态。

## 2. 目标态

适用：介绍 / 总览、设计 / 规格、规范 / 标准、参考 / 速查、概念 / 知识正文、模板。

必须：只陈述对象——有什么、各是什么、做成什么样、接口与流程、必须遵守的约束。
禁止：讨论中的优先级、选型理由、修正说明（「主分类是」「第二轴只决定」「应该走」「我们改成」）。
禁止：否决过的备选（「不要用 Redis」）。
禁止：把其他流程、分流、对照塞进本文（「不要出分镜表」「写不下走多镜」）。
禁止：用「不要 xx」与其他文档划界。

「不要 xx」仅当它是本对象不变量（安全、正确性、不可逆）且改不成正面规则时保留。

## 3. 过程态

适用：ADR / 决策记录、选型对比、复盘、讨论纪要。

必须：写背景、选项、决定、后果。
这类文档的对象就是决策过程。

## 4. 操作

适用：教程、操作手册、runbook。

必须：步骤写做什么、按什么顺序。
必须：「不要」只约束本操作（安全、正确性、不可逆）。
禁止：在步骤里写选型否决、改稿纠偏、与其他文档的分流。

## 5. 改稿

必须：把讨论结论消化成目标态表述，再写入文档。
禁止：在已有目标态正文上追加「不要 xx」「我们改成」「没选 B」。
