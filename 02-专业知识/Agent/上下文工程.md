# 上下文工程

> 本文档目的：介绍上下文工程的概念、构成、核心环节与工程约束，明确上下文压缩在其中的定位。

## 一、什么是上下文工程

上下文工程（Context Engineering）是系统性地管理 Agent 工作过程中上下文的全流程方法论——从信息产生、注入、压缩、检索到移除的生命周期管理。

核心目标：让 Agent 的上下文保持高信噪比——当前任务直接需要的信息在窗口内，不需要的信息不放入或按需拉取。

### 为什么窗口大了也不行——context rot

上下文窗口从 100K 扩到 1M 并没有消除管理需求：

- **context rot（上下文腐烂）**：随窗口内 token 数增加，模型准确召回其中信息的能力下降。needle-in-a-haystack 类基准反复验证，各模型只有程度差异，没有例外
- **注意力预算**：Transformer 中 n 个 token 两两建立注意力关系（O(n²)）；训练数据以短序列为主，模型对长程依赖的经验更少。退化是渐变梯度而非硬悬崖

因此上下文是边际收益递减的有限资源——每个新 token 都在消耗模型的注意力余额。Anthropic 给出的操作目标：找到能最大化期望结果的最小高信号 token 集合。

### 上下文的构成（静态视角）

按信息的作用分三类：

| 类型 | 作用 | 内容 |
|------|------|------|
| 指导性 | 告诉模型做什么、怎么做 | System Prompt、任务描述、few-shot 示例、输出格式约束 |
| 信息性 | 告诉模型需要知道什么 | RAG 召回内容、记忆（对话历史 / 长期记忆）、状态与草稿（TODO、思考过程） |
| 行动性 | 告诉模型能做什么、做了什么 | 工具定义、工具调用记录与结果 |

静态构成回答"有哪些东西可管"，下文的核心环节回答"怎么管"。

## 二、核心环节

### 1. 上下文注入（Injection）

决定什么信息进入窗口，以及什么时候进入。两个子操作：

- **放入**：系统提示词、工具定义、当前文件 / 选区 / 最近编辑、用户输入、项目指令文件（`AGENTS.md`、`CLAUDE.md`、`.cursorrules`）
- **选择/掩码**：从候选集合中只挑与当前任务相关的部分。排除工具不必改动 prompt：Manus 用 logits 掩码——工具定义留在 prompt 里不动，解码时屏蔽不可用工具的 token，前缀不变

核心问题：放多了噪音大，放少了 Agent 缺信息。

压缩后需要重新注入稳定上下文（项目规则文件），防止压缩丢失关键约束。

### 2. 工具输出截断（Truncation）

工具结果进入上下文之前即截断，不等压缩触发。Codex CLI（`tool_output_token_limit`，12,000 tokens）与 Claude Code（Budget Reduction）采用此做法。

被截掉的部分直接丢弃——不在窗口，也不在任何存储层。截断与替换写外置是同一决策点（大工具结果怎么进窗口）上的互斥替代方案；旁路落盘与截断并存，但记录的已是截断后版本。按被排除部分的命运排成谱系：

| 档位 | 做法 | 被排除部分的下场 |
|------|------|----------------|
| 纯截断 | 砍到限额，无标记 | 丢弃，模型不知道内容不完整 |
| 截断+标记 | 留 `... [truncated]` 标记 | 丢弃，但模型知道不完整，可换策略（重跑、缩小查询范围） |
| 截断+指针 | 留片段 + 完整内容路径引用 | 落盘可读回——即替换写外置 |

损失性质分三种：

- 有源头（命令执行、文件读取）：重跑 / 重读即可恢复，截断实际可逆
- 无源头（MCP 调用、外部 API 响应）：无法复现，真丢失
- 无声截断：模型把截断后内容当完整事实，基于残缺数据行动而不自知——最危险

读文件类工具是天然例外——源头在磁盘，截断等于"这次只看了一部分"，无损。

和压缩的区别：截断是"进来之前就砍"，压缩是"进来之后满了才缩"。截断派产品中，截断是比压缩更深的有损层：transcript 记录的就是截断后的版本，压缩后从 transcript 恢复，至多恢复"截断的幸存者"。

### 3. 上下文压缩（Compression）

信息超出窗口时缩减。

- 摘要压缩（对话历史 → running summary）
- token 级压缩（实际用得少）
- 任务交接摘要（Codex CLI 的 handoff summary）

### 4. 上下文外置（Offloading）

把信息落到窗口之外的存储。外置一直在进行，不是满了才触发：

- **全量旁路落盘（底座）**：全部对话历史——不限于大工具结果——逐条实时写入原始层：transcript（Claude Code）、rollout（Codex）、`session_memory`（Trae）、全状态文件化（Manus），外加事件性的状态快照、ghost snapshots，append-only 忠实记录。窗口不动、不省空间；价值在让压缩可逆、断点恢复、记忆策展有底可查
- **大结果替换写（常态，按大小）**：大工具结果不进窗口，落盘后窗口只留路径 + 前 10 行预览（Deep Agents：>20K token）；MCP 工具描述文件化（Cursor：只塞工具名列表，描述按需 grep）——直接省窗口空间
- **阈值外置（兜底，按压力）**：窗口压力超阈值（Deep Agents：85%）时截断历史中旧的 write/edit 调用、替换为文件指针；压缩后聊天历史文件化（Cursor：给 agent 历史文件引用）

两类内容：

- **搬运已有信息（被动）**：工具结果、聊天历史、MCP 工具描述移出窗口
- **主动生成外部状态（note-taking）**：agent 主动写 todo、决策记录、执行状态——主动构建外部状态，而非等窗口满了才被动压缩（Anthropic 将 Structured Note-taking 列为长程任务三大策略之一）

外置的原始层是原始会话记录（见旁路落盘），它是压缩可逆、断点恢复、记忆策展的共同地基。

信息外置是上下文工程的地基环节，当前创新最密集。没有外置，压缩是不可逆的有损操作，检索恢复无从谈起，清理就是直接丢数据。外置让"有损"变成"无损可恢复"，是整个范式从"塞满窗口"转向"按需拉取"的关键支点：

- **压缩的安全性依赖外置**——没有外置，压缩不可逆；有了外置，压缩变成可逆的中间状态（窗口里是摘要，原始数据在外部可找回）
- **检索恢复的前提是外置**——没有外置，agent 无从检索；有了外置，agent 可自主访问文件系统找回细节
- **清理的容错性依赖外置**——没有外置，清理即永久丢失；有了外置，清理后仍可从外部恢复
- **记忆策展的上游是外置**——没有原始记录，策展无从谈起（见环节 9）

反证：Trae 有跨会话记忆文件化（session_memory / topics 落盘，属持久化），但无会话内工具结果外置，上下文管理也最薄弱——靠用户重开会话和精简规则文件兜底，没有系统级的上下文生命周期管理。

### 5. 上下文检索 / 恢复（Retrieval）

从外部按需拉回信息。检索目标对应两层存储，方式不同：

- **外置层（会话内）**：读回外置的工具结果、原始记录——`read_file` / `grep` / `tail`，精确匹配——找的是"被移出去的那段原文"
- **记忆模块（跨会话）**：召回长期记忆、历史对话——语义匹配为主；Claude Code / Trae 用"索引预载 + agent grep 细节"的精确方式，向量检索属 Letta / Mem0 流派；`@Past Chats` 属用户触发

关键区别在触发者：传统 RAG 是"系统决定召回什么"（预先塞入 prompt），Agent 层是"Agent 自己决定拉取什么"——只维护轻量标识符，运行时按需加载（just-in-time retrieval，见「Anthropic 官方框架」）。用户触发（`@Past Chats`、重开会话）介于两者之间：数据可找回，但拉取决策不在 agent。

### 6. 上下文清理 / 驱逐（Eviction）

主动移除不再需要的信息。

- 任务完成后 `/clear`（Anthropic 官方建议第一条）
- 滑动窗口丢弃旧消息

和压缩的区别：压缩是"缩减但保留语义"，清理是"直接移除"。

### 7. 上下文隔离（Isolation）

把子任务交给独立的上下文窗口，主上下文只接收结论。机制上是"另开窗口"，而非在同一窗口内操作。

- 子 Agent：大输出任务交给子 Agent，主对话不超载（Claude Code、Deep Agents）
- Codex CLI 的 `/fork` 派生会话：带着已有背景去试另一种方案，主线程不受影响
- Trae Builder：把大项目分解为小任务

隔离是业界框架中的一等原语（Anthropic 三策略与 LangChain 四操作均单列）——注意力的分布式管理：重活在子窗口发生，主窗口保持高信噪比。

### 8. 上下文路由（Routing）

不同任务阶段用不同上下文，在同一个窗口内操作。

- 任务边界切换时清理旧上下文、注入新上下文

### 9. 上下文持久化（Persistence，记忆模块）

跨会话保留信息。落地形态是记忆模块：策展后的精炼、可注入产物——项目规则文件（`AGENTS.md`、`CLAUDE.md`）、用户偏好（`user_profile.md`）、交接文档（Codex `HANDOFF.md`）、记忆索引（`MEMORY.md`）。

与外置环节是源与派生的关系，不是并列：

```
会话产出 → 外置层（原始记录，全量保真） → 策展（判断什么值得活过这次会话） → 记忆模块（精炼，可注入） → 下次注入
```

- 策展存在决策权归属问题：Codex `HANDOFF.md` 用户手工维护；Claude Code Auto Memory / Trae 记忆由 AI 创建/更新/删除
- `MEMORY.md` 式"指针+摘要"索引活在记忆模块里，但指向外置层——注入时加载索引，细节按需检索

存储与检索实现、巩固机制设计属于记忆模块自身的对象，不在本文展开。

### 环节之间的关系

```
注入（规则/记忆索引） → 工作 → [大工具结果？]
   │ 是 → 替换写外置（落盘，窗口留引用+预览） ← [需要细节？] → 检索恢复
   │ 否
   ↓
组装进窗口 → [满了？] → 阈值外置 → [仍满？] → 压缩 → 重注入稳定上下文
   ↓ 任务完成
清理 → 产出沉淀为原始层 → 策展 → 记忆模块 → 下次注入
```

外置是常态——旁路落盘从第一条消息开始，替换写在工具结果产生时发生，都不是"满了"才触发；压缩是"满了"路径上的兜底，且越来越多地被"外置 + 按需拉取"替代。图中只画影响窗口空间的替换写，旁路落盘不占窗口、不入图。隔离和路由是结构性选择，不是时序步骤，不入图。

本文环节是"操作 × 时序"的展开，与业界操作框架的对应：

| 业界操作 | 本文环节 |
|---------|---------|
| Select（选择） | 注入（含选择/掩码） |
| Compress（压缩） | 截断 + 压缩 |
| Write（外置/写入） | 外置（含笔记、原始记录）+ 持久化 |
| Isolate（隔离） | 隔离 |

### 决策权归属

上述环节回答"对上下文做什么"，"何时做由谁决定"是正交维度——harness 固定规则，或 agent 自主判断。决策权在各环节上呈梯度分布：

| 环节 | 自主程度 | 说明 |
|------|---------|------|
| 检索 | 天然自主 | 工具调用本来就由模型发起 |
| 压缩 | 正在自主化 | Deep Agents 给 agent `compact` 工具，按任务语义判断"这段历史还有用吗"，在任务边界自主调用——从 harness 阈值触发的转移 |
| 外置/笔记 | 可自主 | agent 主动写 todo、决策记录 |
| 策展 | 部分自主 | Codex HANDOFF.md 人维护；Claude Code / Trae 记忆 AI 管理 |
| 注入 | 仍在 harness | system prompt 组装由 harness 控制，模型至多经记忆工具间接影响未来的注入 |

agent 只发出 tool_use 表达意图，上下文的实际修改仍由 harness 执行——转移的是决策权，不是执行权。趋势：随模型变强，决策权从 harness 渐次移向 agent。

### 三个核心环节

九个环节中最重要的三个：

1. **信息外置（地基）**——没有外置，压缩不可逆、检索无从谈起、清理不可容错、记忆无从策展。是整个范式从"塞满窗口"转向"按需拉取"的支点
2. **上下文压缩（核心问题）**——所有产品都有，是上下文窗口有限这一物理约束的直接应对。有了外置后，压缩从"终点"变成"中间状态"，从不可逆变成可恢复
3. **稳定上下文注入+重注入（安全保障）**——所有产品都做了压缩后重注入项目规则文件。没有这一步，压缩会丢掉关键约束（项目规范、安全边界、用户偏好），agent 在压缩后可能行为偏移

三者形成最小闭环：

```
注入稳定上下文 → 工作 → 满了 → 外置+压缩 → 重注入稳定上下文 → 继续
```

注入保证关键约束在窗口里，压缩+外置处理窗口满了的问题，重注入保证压缩后关键约束不丢。

其余环节：隔离和路由是结构性选择，不在会话内时序上，缺了不会限制会话长度——但隔离是业界框架的一等原语；持久化属于跨会话层面，不在会话内闭环中；检索恢复是最前沿方向但当前还没普及为共性；截断、清理是优化项。

## 三、Anthropic 官方框架

Anthropic《Effective Context Engineering for AI Agents》（2025-09）的定义：上下文工程是 prompt engineering 的自然延伸——prompt engineering 关注"对模型说什么"，上下文工程关注"模型在说话时看到什么"。框架分三部分。

**注意力管理（单次调用内）**

精简 system prompt 与工具集。工具定义过多（尤其 MCP 接入后）会稀释注意力，导致选错工具、忽略关键指令。

**长程任务三策略**

| 策略 | 做法 | 对应本文环节 |
|------|------|------------|
| Compaction（压缩） | 接近窗口时摘要旧历史，保留决策锚点——当时改变 Agent 行为方向的关键信息 | 压缩 |
| Structured Note-taking（结构化笔记） | 任务执行中主动把状态、决策、发现写入文件，是主动建设而非等窗口满了才被动压缩 | 外置（笔记） |
| Sub-agent Architectures（子 Agent 架构） | 大输出、可并行的子任务交给独立上下文窗口的子 Agent，主对话只收结论 | 隔离 |

子 Agent 在官方框架中与压缩、笔记并列为三大策略，是注意力的分布式管理，不只是并行优化。

**检索：从预加载到 just-in-time**

传统 RAG 预先检索内容塞入 prompt；Agent 的做法是只维护轻量标识符（文件路径、链接），运行时自主用工具按需加载（just-in-time retrieval）。Claude Code 是混合代表：CLAUDE.md 全量预载，其余靠 grep / glob 即时检索。

## 四、工程约束：Prompt Cache

上下文工程不只决定"塞什么"，还决定"以什么顺序塞"——prompt cache 按前缀匹配。

**成本差**：命中缓存的输入 token 远便宜于未命中，差约 10 倍。生产 Agent 的输入输出 token 比约 100:1（Manus 数据），输入侧成本主导一切——Manus 称 KV-cache 命中率是生产 Agent 最重要的单一指标。

**与压缩的天然冲突**：压缩、删改历史会改变 prompt 前缀 → 缓存失效 → 本次调用反而更贵。省 token 与保缓存是同一操作里的相反力。

**应对方式**：

- Claude Code：分层压缩按对历史的改动幅度递增排列，只有第五层才做全量摘要；cached microcompact 更进一步，用 cache_edits API 在服务端已缓存的前缀上原地删除旧工具结果，零缓存失效
- Manus：工具可用性用 logits 掩码控制（解码时屏蔽不可用工具的 token），而非从 prompt 移除定义——前缀不变，缓存不失效
- 通用做法：稳定内容（system prompt、规则文件）放头部，易变内容放尾部

## 五、上下文压缩的定位

上下文压缩是上下文工程的一个子集——当信息超出窗口时的缩减手段。它解决的是"信息太多怎么办"，而上下文工程解决的是"该有什么、什么时候有、怎么有"。

当前趋势：当 Agent 具备工具调用能力后，压缩可以被"外置 + 按需读取"替代（如 Cursor 的文件化按需拉取、LangChain Deep Agents 的虚拟文件系统）。理想状态是上下文里只有当前任务直接需要的信息，不需要的东西一开始就不放入。

## 六、主流 Agent/IDE 实现对比

### Claude Code —— 五层压缩流水线 + 五层记忆金字塔

压缩不是单一策略，而是一条从廉价到昂贵的分层流水线，在每次调用模型前运行。

**压缩流水线（五层，顺序触发）**

| 层级 | 名称 | 做什么 | 触发条件 |
|------|------|--------|----------|
| 1 | Budget Reduction | 对每条消息的工具输出设大小上限 | 每次工具调用时 |
| 2 | Snip | 裁剪较早的历史段落 | 上下文超阈值 |
| 3 | Microcompact | 基于时间衰减做局部压缩，保留 tool_use/tool_result 关联结构 | 上下文继续超阈值 |
| 4 | Context Collapse | 不修改底层存储，生成只读投影给模型看 | 更高压力 |
| 5 | Auto-compact | 调用 LLM 做完整摘要 | 前四层不够时 |

分层排序的动因：便宜的本地操作先上，昂贵的 LLM 摘要兜底；且按对历史改动幅度从小到大排列，尽量保住 prompt cache 命中（见「工程约束：Prompt Cache」）。

另有 Reactive Compact——当 API 返回 `context_length_exceeded` 时触发的紧急降级，做比 auto-compact 更激进的摘要。auto-compact 触发阈值约为 83.5% 窗口（200K 窗口减去约 33K buffer）。

压缩后触发 `SessionStart('compact')`，重新注入 `CLAUDE.md`、项目规则和 Hook additional context。原始消息仍保留在 JSONL transcript 中，不从磁盘删除。

**记忆系统（五层金字塔）**

| 层级 | 内容 | 加载策略 |
|------|------|----------|
| L1 系统级 | Agent 行为规则、工具 schema、安全约束 | 强制全量加载，常驻 |
| L2 项目级 | `CLAUDE.md`（支持多级作用域） | 启动时加载，压缩后重新注入 |
| L3 持久化记忆 | Auto Memory（`~/.claude/projects/.../memory/*.md`） | 四类：user/feedback/project/reference |
| L4 记忆索引 | `MEMORY.md`（只存指针+摘要，限 200 行/25KB） | 每次会话自动加载 |
| L5 会话级 | 当前任务列表、执行计划、中间状态 | 内存中，结束清空 |

### Cursor —— 动态上下文发现（Dynamic Context Discovery）

范式转移：从"把所有上下文塞进窗口"到"让 agent 按需拉取"。核心是文件作为上下文原语。

| 场景 | 旧模式 | Cursor 做法 | 效果 |
|------|--------|-----------|------|
| 长工具响应 | JSON 全量塞入 | 写入文件，agent 用 `tail`/`read` 按需读 | 减少 summarization 触发 |
| 聊天历史 | 压缩后有损不可逆 | 压缩后给 agent 历史文件引用，可 `grep` 恢复 | 摘要有损但可恢复 |
| Skills | 全文常驻系统提示 | 只放名称+描述，按需加载 `SKILL.md` | 渐进式披露 |
| MCP 工具 | 所有工具描述塞入 prompt | 只塞工具名列表，描述同步到文件夹按需 grep | token 降 46.9% |
| 终端输出 | 手动 copy/paste | 同步到文件系统，agent 直接 `grep` | 与 CLI agent 上下文来源一致 |

### OpenAI Codex CLI —— 双路径压缩 + 任务交接摘要

开源（Rust 实现），上下文管理代码在 `codex-rs/core/src/`。

**双路径压缩**

| 路径 | 机制 | 适用 |
|------|------|------|
| 远程压缩 | 调用 OpenAI `/responses/compact` 端点，服务端返回加密摘要 | 仅 OpenAI 自家模型 |
| 本地压缩 | 客户端用 LLM 生成摘要（`templates/compact/prompt.md`） | 所有模型提供商 |

压缩 prompt：`"You are performing a CONTEXT CHECKPOINT COMPACTION. Create a handoff summary..."`，摘要结构包含：进度/决策、约束/偏好、剩余工作、关键数据。

压缩后保留最近约 20K tokens 的 user 消息原样，其余 assistant 回复与工具结果全部丢弃，空间仍不足时从头截断（head trimming）；mid-turn 压缩时重注入上下文设置，保留 ghost snapshots 供 `/undo`。触发阈值默认为原始窗口的 90%（v0.100.0 起硬上限，只能调低）。工具输出在记录时即截断（`tool_output_token_limit`，默认 12,000 tokens）。跨会话靠用户维护 `HANDOFF.md` 交接文档，支持 `@` 引用跨对话上下文，`/fork` 派生会话做上下文隔离。

2026-09 起另有实验性 token-budget 方案（默认关闭）：token 预算 + history notes + `new_context` 开新窗口，方向是用换窗口替代原地压缩。

### LangChain Deep Agents —— 三级压缩 + 自主压缩

最干净的分层架构，三级按压力递增触发，加一个让 agent 自己决定的工具。

| 级别 | 触发条件 | 做法 | 可恢复性 |
|------|----------|------|----------|
| 大工具结果外置 | 工具响应 >20K token | 写入虚拟文件系统，替换为路径+前10行预览 | agent 可 `read_file` 找回 |
| 大工具输入外置 | 上下文 >85% 窗口 | 截断旧的 write/edit 工具调用，替换为文件指针 | 文件已在磁盘，无损 |
| 摘要压缩 | 外置后空间仍不够 | LLM 生成结构化摘要（含 session intent、artifacts、next steps）；原始消息写入文件系统 | agent 可 `read_file` 找回 |

自主压缩（Autonomous Context Compression）：给 agent 一个 `compact` 工具，让模型自己决定何时压缩。适合压缩的时机——任务边界、消耗大量上下文后获得结论时、即将开始复杂多步操作前、新需求推翻旧上下文时。

### Trae IDE —— 双轨记忆 + 轻量上下文管理

| 类型 | 生效范围 | 存储位置 |
|------|---------|---------|
| 全局记忆 | 所有项目 | `~/.trae-cn/memory/user_profile.md` |
| 项目记忆 | 当前项目 | `~/.trae-cn/memory/projects/{path}/project_memory.md` |

记忆以 Markdown 文件存储，AI 可自动创建/更新/删除。临时指令、模糊偏好、敏感信息不会被保存。另有会话级记忆文件化：`session_memory_*.jsonl`（消息级）与 `topics.md`（主题级）落盘、可 grep 检索——属跨会话持久化，非会话内工具结果外置。其他机制包括 AI 模型按需加载（不常驻内存）、Builder 模式分解大项目为小任务、精简规则文件、控制 MCP 开启数量。

### 其他范式：Manus / MemGPT / Amp

| 产品 | 核心策略 | 一句话哲学 |
|------|---------|-----------|
| Manus | 文件系统即上下文；围绕 KV-cache 设计；logits 掩码管理工具 | 保持边界清晰，然后让开 |
| MemGPT / Letta | 上下文 = RAM、历史 = 磁盘，Agent 自主换页 | 操作系统式内存调度 |
| Amp | `/handoff` 换新线程，历史归档可检索 | 长对话本身是问题，换线程比压缩好 |

- **Manus**：把文件系统当作终极上下文——容量无限、天然持久、Agent 可直接读写；区分压缩（可逆，如旧工具结果替换为引用）与总结（不可逆）；工具可用性用 logits 掩码而非移除，保持 prompt 前缀稳定（见「工程约束：Prompt Cache」）
- **MemGPT / Letta**（2023 论文，后商业化为 Letta）：操作系统隐喻——LLM 是 CPU、上下文窗口是 RAM、外部存储是磁盘，模型自主决定换入换出，包括编辑自己的记忆。是 Deep Agents 虚拟文件系统与 Manus 文件系统上下文的思想前身
- **Amp**（Sourcegraph）：不做递归压缩——反复摘要会保真度衰减（复印件的复印件）；`/handoff` 开干净新线程携带结构化交接要点，完整历史归档供检索。用路由 + 持久化替代压缩；Codex 2026-09 实验的 token-budget 方案与此同型

### 跨产品对比

| 维度 | Claude Code | Cursor | Codex CLI | Deep Agents | Trae |
|------|------------|--------|-----------|-------------|------|
| 压缩层数 | 5 层流水线 | 自动摘要，外置降低摘要频率 | 双路径+截断 | 三级+自主 | 轻量压缩 |

| 稳定上下文重注入 | CLAUDE.md 压缩后注入 | Skills 按需加载 | AGENTS.md 重注入 | AGENTS.md 启动加载 | 规则文件加载 |

### 各环节共性分析

| 环节 | 是否共性 | 备注 |
|------|:---:|------|
| 工具输出截断 | 部分 | 截断派（Codex、Claude Code）纯截断、无替换写外置；外置派（Cursor、Deep Agents、Manus）以替换写外置替代截断 |
| 信息外置 | 是 | 所有产品都有旁路落盘（原始层）；替换写外置为 Cursor、Deep Agents、Manus 所做 |
| 分层压缩 | 是 | 都有，但依赖程度差异大——Claude Code 投入最多，Cursor 刻意最少 |
| 稳定上下文注入+重注入 | 是 | 项目规则文件（AGENTS.md/CLAUDE.md）启动时注入，压缩后重新注入 |
| 原始数据可恢复 | 部分 | 外置派原始数据在盘可找回；截断派的工具输出在记录时已丢失 |
| 隔离 | 是 | 子 Agent（Claude Code、Deep Agents）、/fork（Codex）、任务分解（Trae Builder）；Cursor 无显式隔离 |
| 检索恢复 | 部分 | Cursor、Deep Agents、Manus 做到 agent 运行时自主检索；其他是用户触发或会话恢复 |
| 决策权梯度 | 部分 | 检索天然自主；压缩、策展正在自主化（compact 工具、AI 管理记忆）；注入仍在 harness |
| 清理 | 是 | 多数靠用户主动 `/clear` 或重开会话，系统自动清理偏粗粒度 |
| 上下文持久化 | 是 | 都有项目规则文件；动态记忆的系统化程度差异大 |

尚未成为共性的都聚在"agent 运行时自主"这一侧：检索恢复的"可恢复"多数指"数据没删，用户/系统可以找回"，而非"agent 运行时自己判断需要、自己去拉取"；截断与外置的取舍也仍在分化——这正是决策权梯度正在推进的前沿。

## 七、设计哲学

- 少而精比多而全更好——信噪比优先于信息量
- 让 Agent 自己管理上下文——模型够强时，决策权从 harness 交给 agent
- 压缩是不得已的手段——有更好的上下文管理能力时，压缩角色变小
