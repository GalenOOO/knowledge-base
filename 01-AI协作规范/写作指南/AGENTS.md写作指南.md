# AGENTS.md 写作指南

> 本文档目的：指导如何为任意 AI 协作项目编写一份高质量的 AGENTS.md，使 AI 代理能高效理解项目并正确执行任务。

## 1. AGENTS.md 是什么

AGENTS.md 是面向 AI 编程助手的**项目导航文档**，被各类 AI 工具（Codex / Cursor / Claude Code / Trae 等）在会话启动时自动读取并注入上下文。

- **读者**：AI 编程助手，不是人
- **性质**：地图，不是手册 —— 只指路，不承载细节
- **位置**：仓库根目录（monorepo 可在子目录嵌套，就近优先）
- **篇幅**：60 行最佳，不超过 200 行

## 2. 七大写作原则

### 2.1 写给 AI 看，不写给人看

- 指令精确无歧义：不说"代码要写好"，要说"函数必须有类型注解"
- 命令式语气：用"必须 / 禁止 / 永不"，不用"我们倾向于"
- 避免修辞与情感：不要"我们坚信…"
- 用列表和标题，AI 解析结构化内容比段落更准

### 2.2 极简

- 每次会话都注入上下文，越长越费 token
- 判断标准：**这条规则是不是每次开对话都要让 AI 知道？**
  - 是 → 写入 AGENTS.md
  - 只是这一次任务的临时要求 → 对话里说，别污染文件
- 长内容外置到独立文档，AGENTS.md 只放索引

### 2.3 内容选择

**该写**（每次必知）：
- 项目概述（一句话定位）
- 必备命令（构建 / 测试 / lint）
- 目录结构与"地雷目录"（不能改的）
- 项目特定约束（AI 不会自己猜到的）
- 反复踩过的坑
- 边界（必做 / 先问 / 永不做）

**不该写**：
- 通用最佳实践（AI 已知）
- 临时任务要求
- 长篇架构文档（外置）
- README 内容（项目亮点、安装方式）

### 2.4 三档边界

判断密度最高的一段，建议分三档：

```
必做（Always do）：每次提交前跑测试；commit 用 Conventional Commits
先问（Ask first）：增加新依赖；改 schema
永不做（Never do）：推 main；提交 .env；改 generated/
```

命令式语言执行率远高于"最好不要""尽量"。

### 2.5 踩坑记录是最高价值内容

当 AI 在同一项目重复犯同一错误时，记录一条规则：

```markdown
## 踩坑记录
- **时区处理**：后端所有时间存 UTC，前端转用户时区。AI 曾多次在此时引入 bug。
- **数据库迁移必须用 Prisma**：禁止直接改表结构。
```

直接告诉 AI "这坑踩过了，别再踩"。

### 2.6 分层与就近优先

| 层级 | 位置 | 用途 |
|------|------|------|
| 全局 | `~/.codex/AGENTS.md` | 个人偏好（适用所有项目） |
| 仓库根 | `AGENTS.md` | 项目共享标准 |
| 子目录 | `子目录/AGENTS.md` | 局部规则，就近优先 |

内容过多时：主文件精简 + 引用子文档。

### 2.7 持续迭代

- 当 AI 同一个错误犯两次 → 写进 AGENTS.md
- 让 AI 做 retrospective，把摩擦点沉淀为规则
- 基于真实问题迭代，不要凭空设想规则

## 3. 通用模板

```markdown
# AGENTS.md

<一句话项目定位>。本文件是 AI 代理接手任务前的入口。

## 启动协议

接到任何任务前，按顺序读取：
1. <必读文件1> —— <一句话用途>
2. <必读文件2> —— <一句话用途>（按需）

## 边界

**必做**
- <每次必须执行的规则>

**先问**
- <需要用户确认才能做的事>

**永不做**
- <绝对禁止的事>

## 目录导航

| 路径 | 内容 |
|------|------|
| <path1> | <用途> |
| <path2> | <用途> |

## 必备命令

- `<command>` —— <用途>

## 踩坑记录

（随迭代补充。当 AI 在此项目重复犯同一错误时，在此记录一条规则。）
```

## 4. 反模式

- ❌ 把 README 内容塞进来（AI 不需要"项目亮点""安装方式"）
- ❌ 和其他文档重复（维护成本 + 冲突风险）
- ❌ 写成长篇大论（AI 会忽略长尾内容）
- ❌ 列举所有文件（用目录导航代替）
- ❌ 用条件式语言（"最好别""尽量"）—— 改用命令式
- ❌ 凭空设想规则 —— 基于真实摩擦迭代

## 5. 不同项目类型的适配

| 项目类型 | "必备命令"段 | "边界"段重点 |
|----------|--------------|--------------|
| 代码项目 | build / test / lint | 代码操作、依赖、分支 |
| 知识库项目 | 无 | 文档操作、结构、命名 |
| 文档站点 | build / deploy | 内容范围、风格 |
| Monorepo | 各子包命令 | 子包边界、跨包改动 |
