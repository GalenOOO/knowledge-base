# DeepSeek Harness 架构

> 本文档目的：说明 dsh 的 Cordis 插件树、会话日志、轮次流程与能力 seam。依据官方 `docs/architecture.md`（中文版 `architecture.zh.md`）。

产品形态与四种模式 → [`01-总览.md`](./01-总览.md)。

## Cordis

Cordis 是 dsh 的内核：插件向共享上下文 `ctx` 贡献服务、类型化事件和**可逆副作用**。产品每一部分都是插件，包括模型适配器、工具注册表、会话日志，以及 **agent loop 本身**。

扩展方式是把插件挂到其他插件旁边。注册会在插件卸载时撤销，不存在需要打补丁的特权内核。设计背景见论文 [_A Programming Paradigm for Spatiotemporal Composability_](https://github.com/cordiverse/paper)。

## Profile 与组合包

一次运行的 `dsh` 是启动时按层叠出来的插件树。

- **profile**：Harness home 里的具名组装。列出要叠的组合包、树外插件，以及用户的 `cordis.patch.yml`。发行版模板：`web`、`headless`。
- **组合包（bundle）**：Cordis 配置项及其挂载代码的分发格式，上层始终可以 patch。

`dsh-base` 是每个 profile 的第一层：模型适配器、工具、持久化、沙箱与审批、设置、凭据、遥测。`dsh-web-app` 加浏览器应用；`dsh-headless` 加一次性运行器。

叠放顺序：profile 列出的各组合包 → profile 的 `cordis.patch.yml` → home 级 patch → `--patch` overlay。查看实际启动树：

```sh
dsh --profile web --dump-config
```

## 核心包

| 包 | 职责 | `ctx` 键 |
|---|---|---|
| `core/session` | 仅追加的 `SessionEvent` 日志与内存存储 | `ctx.sessions` |
| `core/system-prompt` | 提示词片段与工具 schema 组装 | `ctx.systemPrompt` |
| `core/tools` | 作用域化工具注册表与带把关的执行流水线 | `ctx.tools` |
| `core/agent` | `Agent` 接口、活跃注册表、`agent/*` 事件 | `ctx.agents` |
| `core/agent-loop` | 实现该接口的默认驱动器 | `ctx.agentLoop` |
| `core/scope` | 按 agent 划分作用域的注册原语 | 无 ctx 键 |
| `llm/llm` | 消息/流式词汇表与适配器 seam | `ctx.llm` |

仓库里还有 skills、compaction、subagent、sandbox、MCP 客户端、ACP server、hooks（对接 Claude Code / Codex）、plan、goals、workflow、self-modification 等包，同样以插件形式挂上。

## 事件三域

| 域 | 用途 |
|---|---|
| **会话事件** | 追加到日志，经 `session/event` 广播；必须在 reload 后仍存在的事实 |
| **Agent 事件**（`agent/*`） | 携带活跃 `Agent`：inbox、步骤、状态、请求、验证、续跑；观察或拦截进行中的工作 |
| **能力事件** | 向 seam（`fs/*`、`tools/*`、`telemetry/*` 等）附加策略与适配器，不必导入 loop |

## 轮次流程

**步骤（step）** = 一次模型请求 + 它调用的工具。**轮次（turn）** = 零个或多个步骤：领取首条输入前打开，不再欠工作时关闭。

```text
turn/start
  claim next-step input plus one queued message
  assemble prompt sections + tool schemas
  -> agent/pre-step                   reject | enter(messages)
     step/start
     append entered messages as user/message
     derive model history from the log
     agent/request -> llm/stream -> assistant/chunk* -> assistant/message
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
     step/end
     tools owe another request, or next-step input arrived -> claim -> next step
  -> agent/turn-stopping
turn/end
```

`turn/*`、`step/*`、`user/message`、`assistant/*`、`tool/*` 是持久会话事件。`agent/pre-step`、`agent/request`、`llm/stream` 与三个 `tools/*` 是 waterfall，监听器必须 `next()` 才能委托下去；`agent/turn-stopping` 是 serial，没有 `next()`。

`agent/pre-step` 决定模型看见什么。监听器可改写或拒绝已领取的消息；首次领取被拒绝或改空，仍会关闭一个不含步骤的持久轮次，日志记下这次尝试。

## 会话日志

会话日志是模型所见上下文的来源。`deriveMessages()` 从中投影出模型历史；原始 `assistant/chunk` 保证回放与 UI 保真。fork、恢复、transcript、遥测、持久化都派生自同一条流。

运行时不变量：**模型可见即已记录**。抵达模型请求的一切必须能从日志重建。因此新增一种模型可见输入，就要扩展 `SessionEventMap` 并从日志渲染。

## 能力 seam

一个 **seam** 是可替换能力，三种角色缺一不可：

1. **Service Definition**：声明接口
2. **Service Provider**：实现
3. **Consumer**：使用方，通常是面向模型的工具

文件系统与进程提供方共享同一个执行世界：把它们指向远程沙箱，Bash、PTY、LSP 一并搬走。subagent 提供方走同一接口，实现可以从新建子 agent，到把一个轮次委派给另一个产品。

## 常见扩展落点

| 目标 | 机制 |
|---|---|
| 加模型提供方 | 在 `ctx.llm` 注册适配器 |
| 加面向模型的能力 | 在 `ctx.tools` 注册，schema 进入提示词组装 |
| 让某会话用不同能力集 | 组装 agent preset；服务行需要 `isolate` realm |
| 加 shell / 终端 | `ctx.shell` / `ctx.terminals` |
| 拦截请求、工具或轮次 | `agent/*` 或 `tools/*`；`agent/turn-stopping` 停轮次 |
| 加模型可见上下文 | `agent.inject()`，落到下一次获准的请求 |
| 加持久会话状态 | 扩展 `SessionEventMap` |
| fork 会话 | `ctx.sessions.fork(...)` |
