# Agent Harness 业界对照

> 本文档目的：把 DeepSeek Harness 放进 2026 年 harness 讨论里，列出业界在谈什么、各产品各自是什么。信息截至 2026-08-17。

dsh 自身 → [`01-总览.md`](./01-总览.md)、[`02-架构.md`](./02-架构.md)。

## Harness 这个词在指两层

| 层 | 指什么 | 代表表述 |
|---|---|---|
| **运行时** | 模型外面的循环、工具、沙箱、会话、权限、UI | DeepSeek：Agent = Model + Harness |
| **使用侧工程** | 用户在仓库里堆的规则、测试、脚本，让 agent 少重复犯错 | Hashimoto 的 harness engineering；Böckeler 的 guides + sensors |

两层常被同一个词罩住。dsh 做的是第一层（开源运行时）；Hashimoto / OpenAI Codex 团队文章大量写的是第二层（把环境改到 agent 能自检）。

## 2026 上半年的共识

- **同一模型、不同 harness，分数可以差一截。** 公开评测里出现过约 10–34 分的摆动（SWE-bench 类、以及同一模型换 8 套 harness 的对比）。
- **切换成本在 harness，不在模型。** 记忆、权限、hooks、skills、会话记录都停在 harness 里。LangChain 2026-04 的说法是：谁控制 harness，谁控制 agent 的记忆。
- **产品形态在收敛：** ReAct 循环、统一工具接口、沙箱、hooks、skills、subagents、MCP、`AGENTS.md` / `CLAUDE.md`。
- **HaaS：** 从「调补全 API」变成「调一套带循环的运行时」。对应物：Claude Agent SDK、Codex CLI / App Server、OpenAI Agents SDK、dsh。

术语出处（按时间）：

- 2026-02-05：[Mitchell Hashimoto, *My AI Adoption Journey*](https://mitchellh.com/writing/my-ai-adoption-journey) — 每次 agent 做错就改环境，使之不再发生，称为 harness engineering。
- 2026-02-11：[OpenAI, *Harness engineering: leveraging Codex in an agent-first world*](https://openai.com/index/harness-engineering/) — 三人团队约五个月、约 1500 个 PR、代码由 agent 写；工程师做的是让 UI、日志、指标对 agent 可读，并加上自审循环。
- 2026-04：[Birgitta Böckeler @ martinfowler.com, *Harness engineering for coding agent users*](https://martinfowler.com/articles/harness-engineering.html) — 外层 harness = feedforward **guides**（提示、约束）+ feedback **sensors**（测试、类型检查、评审 agent）。

## 主流 coding agent 运行时

| 对象 | 形态 | 特点 |
|---|---|---|
| **Claude Code** | 闭源终端产品 + Claude Agent SDK | 完整工具集、hooks、Agent Teams、MCP；loop 是产品中心，扩展插在 loop 周围 |
| **OpenAI Codex** | 开源 CLI + 云端沙箱 + App Server（JSON-RPC） | 循环、工具分发、context compaction 做成可嵌入运行时；云端子 agent |
| **Cursor** | IDE 内嵌、模型可换 | 代码索引 retriever，减少整文件塞上下文 |
| **OpenCode** | 开源 MIT | 强调 75+ 模型后端，同一界面换提供方 |
| **Pi** | 开源、极简 | 核心小；扩展插在 loop 周围的 Host ABI（tools、commands、skills、lifecycle、context transform） |
| **DeepSeek Harness** | 开源 MIT，developer preview | **loop 本身也是插件**；不可换的是 session log，不是 loop |

Pi 与 dsh 的社区对照（GitHub Discussion #1023）：两边都把「固定钩子点」改成「运行时由组合构成」。差别是重心——Pi 的 loop 仍是产品，扩展是市场；dsh 把能力拆成 Cordis 的 service / provider / consumer，session 的仅追加日志才是权威。已有 `pi2dsh` 一类桥，把 Pi 包挂进 dsh profile。

dsh 另有 Claude Code / Codex 的 subagent 提供方（后来从 `dsh-base` 挪到 examples，需显式依赖），以及 hooks 桥、MCP 客户端、ACP server，并读取 `AGENTS.md` / `CLAUDE.md`。

## Code Mode

工具调用的另一条路径：不要一次一次 function calling，让模型对着 typed SDK **写一段代码**，在沙箱里执行，把多步编排压进一次。

| 来源 | 做法 |
|---|---|
| Cloudflare *Code Mode* | 模型写 TypeScript，在 Dynamic Worker 里跑；MCP 侧可收成 `search()` + `execute()` |
| Anthropic *Code Execution with MCP* / Programmatic Tool Calling | 同类：用代码编排 MCP 工具 |
| dsh **Code mode** | Standard 能力经 Code Mode SDK 暴露，模型写 TypeScript，由 `run_code` 派发嵌套工具调用 |

## 和「模型厂只发权重」的关系

dsh 出现在 DeepSeek-V4 同期。公开评论里的读法是：中国实验室开始在 **运行时层** 和 Claude Code / Codex 抢同一块，而不只是基准分数与价格。dsh 当前仍是 developer preview，插件 ABI 会变；它是可组合框架，不是开箱即用的 Claude Code 替代品。
