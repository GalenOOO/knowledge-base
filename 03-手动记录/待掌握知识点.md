# 待掌握知识点

> 本文档目的：系统列出要掌握的范围，不记录具体知识点。

# 基础知识

## harness

1. **边界**：和模型各负责什么；同一句话里「运行时」和「使用侧工程」分别指什么
2. **目标**：补齐能力、受控执行、过程可观测，这三件事各自约束什么
3. **循环**：turn / step / 工具调用 / 观察回填如何组成一次任务；何时停
4. **能力面**：tools、memory、context、skills、subagent、MCP 各自解决哪类问题，缺了会怎样
5. **控制面**：sandbox、权限、文件系统、hooks 各自卡在哪一步
6. **上下文**：什么必须进模型、什么只放在环境里；组装、压缩、截断、缓存各自解决什么
7. **扩展**：哪些可换、哪些是不变量；插件 / SDK / 配置 / 约定文件各适合改什么
8. **形态**：CLI、IDE、SDK、HaaS；function calling 与 Code Mode 差在编排方式
9. **比较轴**：loop 是否可换、工具是否内置、记忆停在哪、扩展插在哪；换 harness 为什么比换模型贵
10. **使用侧**：仓库里的约定、测试、反馈怎么写成 agent 可执行的环境，而不是再写一份给人看的手册

## 多 Agent

1. **任务类型**：固定流程编排和开放协作各适合什么，复杂任务为什么会落到多 Agent
2. **拆分**：按什么切（阶段、角色、技能、上下文隔离）；协调者、执行者、评审者各干什么
3. **协作**：怎么派活、交接口、汇总；何时自动组 swarm，何时人手定拓扑
4. **自主程度**：约束到什么粒度；过度限制和完全放养各会坏在哪
5. **对错**：没有标准答案时，如何判定结果、如何把判定做成可重复的信号

## memory

### 1. 记忆类型

1. **为什么需要**：模型无状态；上下文窗口不是记忆
2. **按内容分**：工作记忆、情景、语义、程序各回答哪类问题；和权重记忆、外部知识库、待办/目标怎么划界
3. **按时间分**：会话内、跨会话、跨用户
4. **生命周期**：谁写、何时读、如何更新/冲突/遗忘；一层如何升级到另一层
5. **放错的后果**：各层写错或漏检，影响范围差在哪

### 2. 不同方案，适用场景

1. **架构形态**：只靠上下文、检索层、图谱、文件系统、agent 自己用工具管理、整套运行时内建
2. **选型轴**：谁来写（自动抽 vs 模型决定）、事实会不会随时间变、和 loop 的耦合度、人能不能审、成本在写还是在读
3. **失败模式**：污染、膨胀、记错当事实、该调工具的进了记忆

## 自演进

1. **改什么**：产物、prompt/memory/tools/skills/工作流、模型权重；文件和运行时逻辑何时算同一层
2. **活多久**：本会话、跨会话、跨用户；越往后越要治理
3. **闭环**：反馈从哪来（测试、评测、环境、人审）；环关在 benchmark、代码还是真实世界
4. **路径族**：复盘、提示优化、playbook、造 skill/工具、再训练；各自改哪一层、要什么信号
5. **和 memory 的交界**：何时只是「记住」，何时已经在改默认行为
6. **风险**：细节被越改越短、错误被写进默认、无法回滚

# 开源项目

对照时只看开源运行时。Claude Code、Cursor 是闭源产品，不放这里。记忆层（Mem0、Letta、Graphiti 等）放在 memory，不单列项目。

## Pi Agent

1. **定位**：在 coding agent / harness 谱系里站哪一端（极简、可扩展、可嵌入）
2. **取舍**：默认提供什么、故意留给扩展的是什么
3. **结构**：LLM 适配、loop、UI、CLI 如何分层；会话和上下文怎么管
4. **扩展**：扩展能插进哪些点；包/技能/提示如何分发；几种运行方式各给谁用
5. **自修改**：缺能力时当场改自己，属于自演进的哪一层、风险是什么
6. **适用**：什么任务适合用它当底座，什么任务它默认不够

## DeepSeek Harness

1. **定位**：它是运行时还是模型客户端；「一切皆插件」改的是哪一层
2. **不变量与可换物**：会话/日志、loop、工具、模型适配各自能不能换
3. **组装**：profile、组合包、运行模式各自决定什么
4. **和 Pi 对照**：扩展插在 loop 周围，还是 loop 本身也可换；各自适合当产品还是当底座
